# 数据准备

## 目录格式

一个数据集目录包含两个必需文件和一个可选文件：

```text
data/processed/frcsub/
├── responses.csv
├── q_matrix.csv
└── items.csv
```

### `responses.csv`

第一列必须为 `student_id`，其余列为题目。行是学生，值只能是 0 或 1；当前版本不接受缺失值。

```csv
student_id,item_001,item_002,item_003
s_001,1,0,1
s_002,0,0,1
```

### `q_matrix.csv`

第一列必须为 `item_id`，其余列为属性。题目集合必须与 `responses.csv` 完全一致，加载时会按作答列顺序重排。

```csv
item_id,borrow,subtract,whole_number
item_001,1,1,0
item_002,0,1,1
item_003,1,1,1
```

每题至少要求一个属性。当前穷举 DINA 实现支持 1–16 个属性；FrcSub 的 8 属性在该范围内。

### `items.csv`

真实 LLM 生成必需，离线统计基线可省略。`item_id` 必须覆盖全部题目，`text` 是模型看到的题目原文，`answer_key` 用于最终答案精确匹配评分。

```csv
item_id,text,answer_key
item_001,"Question text here","3/8"
```

当前评分器做 Unicode NFKC、大小写和空白归一化后的精确匹配。正式使用 FrcSub 前，应增加并验证分数等价、多表示答案和干扰项的专门评分规则；不要把数值等价判断交给 LLM。

## 拟合与留出

`execute_pilot` 以固定种子随机按学生对半切分。所有基线参数、人设分布和回读模型只由拟合半估计，保真度统一以留出半为参照。正式研究需在外层重复整个切分 B 次，而不是只重复生成。

## FrcSub 入库前检查

- 核对所用版本确为 536 × 20、8 属性及对应专家 Q 矩阵；
- 从原始文献核对 20 道题原文、正确答案和评分规则；
- 记录数据来源、下载日期、原始文件校验和与许可；
- 不在仓库中提交真实数据，除非许可明确允许再分发；
- 为同构改写题单独保存题目版本字段，并确认改写后 Q 矩阵不变。

## 第二数据集与 RQ3

学生级作答、题目原文、可用许可、可信 Q 矩阵四项齐备，才进入维度 A+B。学科标签不能直接当作经过验证的认知属性。只有保留学生级、跨题、具体干扰项选择的数据才能支撑 RQ3；Eedi Kaggle 2024 的错误概念分类表本身不构成真人作答对照。
